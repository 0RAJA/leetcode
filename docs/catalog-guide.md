# 题解导航的使用与维护

## 打开导航

线上地址：[算法手记](https://0raja.github.io/leetcode/)。导航右上角可返回[个人博客](https://blog.humraja.top/)。

在本地用浏览器打开 `docs/explorer/index.html` 即可。页面和数据均在仓库内，不依赖在线题库接口，也不需要安装前端依赖。

需要通过本地地址访问时，在仓库根目录运行：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

然后访问 <http://127.0.0.1:8765/docs/explorer/>。GitHub 不会执行文件列表中的 HTML；直接在 GitHub 阅读时使用 [Markdown 题解索引](CATALOG.md)。

搜索题号、题目名或题型，点击题目查看关联思路、Go 代码、历史版本及测试入口。待复习标记只保存在当前浏览器，换设备前可用页面的导出功能备份；这些标记不修改仓库。

## 用它帮助下一次独立做出来

- **先回忆**：详情默认不展开答案。先打开原题，回忆题型、关键不变量或状态、边界例子；再主动点开原笔记或 Go 代码。
- **连着比较**：切到“关联路径”，按同一思路的变化回顾几道题。详情里的“下一步对比／回到基础”说明具体比较什么；关联跳转后可以返回上一题，原筛选条件保留。
- **标出下一次要练的题**：“需要再练”会加入待复习，“能独立写出”会移出队列。开始复习时优先选择当前结果中的待复习题，并把最近自评过的题往后放。不根据打开笔记或查看代码推断掌握程度。

自评和待复习均只在浏览器里保存，可以一起导出。旧版只有待复习题号的导入文件仍然可用。导入采用合并；不会删除本机已有的标记。自评可单独清除，清除时保留待复习标记。

从本地文件切换到线上地址，或换浏览器、设备时，先在原页面导出标记，再到新页面导入。各地址和浏览器的本地存储相互独立，不会自动同步。

## 题目关系从哪里来

**精选对比路线**在 `docs/explorer/learning-paths.js` 中维护，目前只有 6 条、21 道题。每一步都要说明状态、不变量或边界发生了什么变化。这是复习建议，不是官方课程或个人掌握记录。测试会检查题号、源码引用和关系说明。

**自动关联**直接读取现有题型，不需要给新题手工连线。只共同拥有“数组”“字符串”等宽泛标签时不推荐；共享较具体题型时提供候选，并明确显示“自动关联 · 共同题型”。同标签仍可能有不同解法，因此只用作比较入口。

筛选关系图时保留路线的前后文，匹配题正常显示，其他步骤淡化。没有覆盖精选路线的题仍可从列表和详情中的自动关联查找。

## 维护成本

| 内容 | 平时需要做什么 |
| --- | --- |
| 题目、题型、代码、原笔记、测试入口 | 继续现有写题方式，索引自动生成；缺少插件元数据或其他平台题才需要补配置 |
| 全库相关题候选 | 按题型自动计算，无需逐题维护边列表 |
| 6 条精选路线 | 偶尔补充真正有比较价值的一步；不为每道新题编排课程 |
| 自评和待复习 | 一次点击，按需导出备份；不部署数据库或账号服务 |
| 语法高亮 | 固定版本的本地 highlight.js，包含许可证和来源校验信息；按需手动升级 |

页面仍是静态 HTML、CSS、JavaScript，没有前端构建或在线依赖。Go 原码及笔记代码块在本地高亮，复制保留原文。代码高亮库约 129 KB；主索引数据约 0.8 MB，包含已收录题解，查询时不用请求远端题库。

把维护精力优先放在自己的关键思路、容易出错的边界和必要自测。精选路线的说明与原始笔记分开保存；原始笔记保留原文，生成索引并不等于校验其中所有算法结论。

## 自动索引的范围

1. `leetcode/editor/cn/pXXXX/solution.go`：通过 `all.json.questionId` 查找页面题号，不能把目录数字直接当题号。
2. `2026/` 等自定义路径：在根目录 `catalog.config.json` 的 `sources` 中配置。
3. 已入库的 `_legacy/` 历史 Go 文件：按题号与标题归并，同题保留多个版本入口。
4. `2026/README.md` 的顶层编号笔记：按实际题号或明确题名匹配，保留原文；只有标题的路线条目不算思路笔记。
5. 已入库且非空的 `leetcode/editor/cn/doc/note/*.md`：按文件名题号与题名匹配。

只读取 Git 已跟踪的文件，不扫描题面缓存、登录态或 IDE 配置。新源码首次运行前需先 `git add` 对应文件；不必提交后再生成。无法可靠映射的文件会列在索引的“待补映射”中。

`all.json` 是已有元数据快照，仅用于题号、题名、难度和题目链接。不会使用其中的历史 `status` 作为当前通过状态。

## 日常更新

继续写代码和原有笔记。需要马上本地预览时：

```bash
python scripts/build_catalog.py
```

推送到 `master` 后，`Build catalog and deploy Pages` 工作流会生成最新索引并运行验证；通过后，把 `docs/explorer/` 作为静态网站发布到 GitHub Pages，同时在需要时用机器人提交概览和 Markdown 目录的更新。不需要 LeetCode 登录态。

Pages 发布来源使用 GitHub Actions，部署环境为 `github-pages`，仅 `master` 分支的推送或手动运行会发布。拉取请求只检查，不部署。站点只打包导航目录，不打包整个仓库。

如果分支保护不允许机器人推送，请在本地运行上述命令后一起提交。仓库在 Actions 设置中禁用工作流时，自动刷新也不会执行。拉取请求中仅验证生成与测试，不会回写分支。

自动生成的文件是 `docs/explorer/data.js`、`docs/CATALOG.md`、`docs/assets/catalog.svg` 和 README 中的 `catalog:start` / `catalog:end` 区域。请修改源题解、笔记或配置后重新生成。

## 元数据缺失时

在 `sources` 中按路径添加自定义题解：

```json
{
  "2026/example/solution.go": {
    "id": "自定义 001",
    "title": "示例题目",
    "url": "https://example.com/problem/001",
    "topics": ["数组", "前缀和"]
  }
}
```

需要修正题型时，在 `overrides` 中用**页面题号**覆盖，例如 `"1": {"topics": ["数组", "哈希表"]}`。没有可靠依据的难度保留“未标注”。

## 展示口径

- 当前维护：至少有一份标准目录或自定义目录中的当前源码。
- 历史归档：只有 `_legacy/` 里的版本。
- 关联笔记：至少有一条非空思路，保留原文，内容是否正确仍由复习时判断。
- 带测试文件：存在对应测试文件，不表示测试已经运行或通过。
- 统计按页面题号去重；同题多种题型会分别计入题型数量。

不自动公布最近提交日期、连续刷题天数或每日活跃度。公开仓库中的提交历史仍由 GitHub 正常提供。

维护工具验证：

```bash
python scripts/build_catalog.py --check
python -m unittest discover -s scripts -p "test_*.py"
node --test scripts/study-model.test.cjs
```

Python 和 Node 仅用于生成与验证；直接浏览页面不需要安装它们。
